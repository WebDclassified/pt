# Phase 11 — Project Case Study System

## Objective

Turn projects into proof of engineering ability, not technology lists.

## Project card anatomy

Each featured project should show:

- number
- name
- concise description
- role
- stack
- year/status where verified
- live demo if verified
- GitHub if available
- case study link

## Case study anatomy

1. Overview
2. Problem
3. Context
4. Goal
5. Role
6. Constraints
7. Architecture
8. Tech stack
9. Key features
10. Engineering challenges
11. Decisions/trade-offs
12. Security
13. Performance
14. Testing
15. Deployment
16. Results
17. Lessons learned
18. Future work
19. Links

Not every project needs every section, but the strongest projects should expose enough depth to prove engineering judgment.

## Evidence hierarchy

`claim → example → demo → case study → architecture → code → result`

## Project-specific creative metaphors

### Vizquo

Inspection/X-ray.

Surface → select → inspect layers → design system → responsive/accessibility evidence.

Do not fabricate internal architecture details.

### Qupay

Transactions and secure money movement.

Use careful visual language—financially precise, not crypto-neon.

Potential layers only where supported by actual project:

- authentication
- accounts
- balances
- transactions
- API
- database

### Hilo

Social graph.

Visualize:

- users
- posts
- comments
- interactions

### Medium Blog Platform

Publishing/editorial architecture.

Show:

- user
- document/blog
- relational model
- authentication

### Block Swap

Transaction/network visualization.

Keep it clearly positioned as a blockchain-inspired learning/interface project, matching the source description.

### Wallet App

Backend/data architecture.

Focus on:

- user data
- balances
- API
- auth
- error handling

## Project truth rules

Only display performance/results after measurement or authoritative source verification.

Never invent user counts or “X% faster” claims.

## Gate

PASS only when each featured project page answers what it is, why it exists, what Prabhat did, how it works, what was difficult, and how someone can verify the work.
